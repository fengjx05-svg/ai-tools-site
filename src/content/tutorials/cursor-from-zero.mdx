## 什么是 Cursor？

Cursor 是一个基于 VS Code 的 AI 编程编辑器。简单说：**它就是你熟悉的 VS Code，但里面住着一个 AI 程序员**。

和 Claude Code（终端工具）不同，Cursor 有完整的图形界面——你能看到 AI 要改什么、按一下按钮同意或拒绝、像聊天一样让 AI 解释代码。

| 特性 | Cursor | Claude Code |
|------|--------|-------------|
| 界面 | VS Code 图形界面 | 终端命令行 |
| 学习曲线 | 低（会用 VS Code 就会用） | 中高（需要命令行基础） |
| AI 角色 | 助手（你主导，AI 辅助） | Agent（你描述目标，AI 自主执行） |
| 代码补全 | Tab 实时补全，预测 2-3 行 | 无实时补全 |
| 适合初学者？ | ✅ 训练轮模式，安全可控 | ⚠️ 终端界面可能让新手觉得陌生 |

**如果你刚入门 AI 编程，Cursor 是更好的起点。** 它有训练轮效应——让你在安全的图形环境里熟悉 AI 协作方式，习惯了再考虑 Claude Code。

## 安装与初始配置

访问 [cursor.com](https://cursor.com) 下载对应版本（Windows / macOS / Linux）。

安装后做三件事：

1. **导入 VS Code 设置**（如果你之前用 VS Code）：Cursor 会提示一键导入，扩展、主题、快捷键全保留
2. **开启隐私模式**（Settings → Privacy Mode）：代码不被远程存储，适合敏感项目
3. **选择默认模型**：在右下角模型选择器里勾选你要用的模型。初学者建议勾上 Claude Sonnet 和 GPT-4o

不需要额外装插件——Cursor 原生支持 Python、TypeScript、Go、Rust 等主流语言的智能提示。

## 四种核心模式（按使用频率排列）

Cursor 有四种 AI 交互方式。按使用频率排列：

### 1. Tab 补全（最常见的入口）

一边写代码，一边按 `Tab` 接受 AI 建议。Cursor 会预测你接下来要写的 2-3 行代码——写完一个函数名，它把参数类型、返回值和简单逻辑都补上了。

```
你：function calculateTotal(
AI 自动补全：  items: CartItem[],
AI 自动补全：  discount?: number
AI 自动补全：): number {
AI 自动补全：  const subtotal = items.reduce((sum, item) => sum + item.price, 0)
AI 自动补全：  return subtotal * (1 - (discount ?? 0))
AI 自动补全：}
```

按 `Tab` 接受整行，按 `Ctrl+→` 只接受一个词。这是你用得最多的功能，也是最容易上手的。

### 2. Inline Edit（Cmd/Ctrl+K）

选中一段代码，按 `Cmd+K`（Mac）或 `Ctrl+K`（Windows），告诉 AI 你想怎么改：

```
选中：function getData() { ... }
按 Cmd+K 输入："加 try-catch 错误处理，失败时返回默认值而不是抛异常"
→ AI 重写整个函数，你按 Accept 或 Reject
```

**典型场景**：重构函数、加错误处理、改变量名、提取子组件。比手动改快 3-5 倍。

### 3. Chat / Ask（Cmd/Ctrl+L）

打开侧边栏聊天窗口，像微信一样和 AI 对话。可以：
- 问"这个文件是做什么的？"
- 让它解释某段复杂的逻辑
- 让它找一个 bug 在哪里
- 让它给出改进建议

Chat 模式**只分析不修改**——AI 给你解释和建议，你自己决定改不改。这是学习代码的最佳方式。

### 4. Agent / Composer（Cmd/Ctrl+I）

这是 Cursor 的"大招"。Agent 模式能：
- 跨多个文件修改代码
- 自己写测试并运行
- 测试失败后自己修 bug 重跑
- 直到全部通过

```
按 Cmd+I，输入：
"在 src/components/ 下新建一个 ErrorBanner 组件，支持 success/warning/error 三种类型，写好单元测试"

Agent 会：
1. 创建 ErrorBanner.tsx
2. 创建 ErrorBanner.test.tsx
3. 运行 npm test
4. 如果失败，读报错、修代码、重跑
5. 全部通过后告诉你"完成"
```

**注意**：Agent 很强大，但每一步改动都要审查。把它当成一个非常勤奋的实习生，而不是一个无需检查的专家。

## @ 引用系统 — 给 AI "指路"

Cursor 最有用的功能之一是 `@` 引用。按下 `@`，你可以：

| 引用类型 | 用途 | 例子 |
|----------|------|------|
| `@Files` | 让 AI 读特定文件 | `@src/utils/auth.ts 这个函数有什么安全问题？` |
| `@Folders` | 让 AI 了解整个目录 | `@src/components 帮我把所有组件的 prop 类型统一导出` |
| `@Codebase` | 让 AI 了解整个项目 | `@Codebase 用户认证在哪些文件里实现的？` |
| `@Web` | 让 AI 搜索网页 | `@Web React 19 的 use() API 怎么用` |
| `@Docs` | 引用官方文档 | `@Docs 用 Next.js 15 的 Server Actions 重写这个 API` |
| `@Git` | 引用 Git 历史 | `@Git 上周谁改了 auth.ts？改了什么？` |

**不用 @ 的后果**：AI 只能"盲猜"你的项目结构，准确率大幅下降。用了 @，AI 基于真实代码回答，准确率高很多。

## 初学者的标准工作流

我推荐这个"三步法"，每次写新功能都用：

```
第 1 步：Plan（Chat 模式，Cmd+L）
"我想给用户注册加上邮箱验证功能。先分析现有代码，告诉我需要改哪些文件、各自改什么。不要写代码。"

第 2 步：Implement（Agent 模式，Cmd+I）
"按上面方案实现。每次改完一个文件暂停，让我审查。"

第 3 步：Review（Chat 模式，Cmd+L）
"Review 刚才的改动，有没有安全问题、遗漏的边界情况？"
```

**关键原则**：Plan 阶段想清楚，Implement 阶段小步快跑，Review 阶段不当甩手掌柜。

## 新手最常见的四个坑

### 坑 1：一次让 AI 做太多

❌ "帮我把整个项目从 JavaScript 改成 TypeScript"
✅ "先把 src/utils/format.ts 改成 TypeScript，我审查通过后继续"

一次一个文件或一个模块。AI 不是上帝，任务越大错误越多，改错的成本也越高。

### 坑 2：不审查直接 Accept

AI 写的代码看着像回事，但可能：
- 引入了安全漏洞（SQL 注入、XSS）
- 遗漏了边界情况（空值、超长输入）
- 用了过时的 API

**每条 AI 生成的改动，至少扫一眼。** 看不懂的地方用 Chat 问"这段为什么这么写？"

### 坑 3：不给上下文

❌ "帮我加个功能"
✅ "@src/app/api/auth/route.ts 在登录接口返回的 JWT 里加上用户的 role 字段，参考 @src/types.ts 里的 User 类型"

给了上下文，AI 的准确率从 60% 飙到 90%+。@ 引用是免费的工具，不用白不用。

### 坑 4：不写测试就用 Agent

Agent 自己写代码 → 自己跑 → 自己修的模式听起来完美，但如果没有测试，Agent 不知道"怎么算做对了"。结果是它能跑通但逻辑不对。

**正确做法**：先让 Agent 写测试用例 → 审查测试 → 再让 Agent 实现代码并跑到测试通过。

## 总结

| 阶段 | 核心动作 |
|------|---------|
| 第一天 | 安装 → 熟悉 Tab 补全 → 试 Cmd+K 改一段代码 |
| 第一周 | 用 Chat 问代码问题 → 学会 @Files 引用 → 小任务用 Agent |
| 第二周 | Plan → Implement → Review 三步法 → 配置项目 Rules |
| 一个月 | 用 Agent 独立完成功能模块 → 考虑是否搭配 Claude Code |

Cursor 的核心价值：**让你在熟悉的 VS Code 环境里，以安全可控的方式学会和 AI 协作编程。**

它不是替代你编程，而是加速你编程。你仍然需要理解代码、做架构决策、审查 AI 的输出。把它当成一个 7×24 小时在线的编程搭档，而不是一个"全自动代码生成器"。

## FAQ

### Cursor 免费版够用吗？

用于体验和轻度学习够用。免费版每天有一定额度的基础请求，但 Tab 补全和 Agent 模式受限较明显。如果每天编程超过 1 小时，建议直接上 Pro（$20/月），体验差距很大。

### Cursor 和 VS Code + GitHub Copilot 有什么区别？

Copilot 主要做 Tab 补全和简单聊天。Cursor 的 Agent/Composer 模式能跨文件自主完成任务，Chat 能深入分析整个代码库。如果你已经在 VS Code + Copilot，切到 Cursor 的学习成本几乎为零（界面一样），但 AI 能力提升显著。

### 我需要会命令行才能用 Cursor 吗？

不需要。Cursor 是图形化 IDE，所有操作都能通过界面完成。但如果你能学会基本的终端操作（`cd`、`npm install`、`git commit`），配合 Cursor 用会更高效。

### Cursor 支持中文吗？

支持。你可以用中文和 AI 对话、提问、描述需求。AI 理解中文没有问题，但代码注释建议用英文（更通用）。

### 我该先学 Cursor 还是先学编程？

如果你完全零基础（没写过一行代码），建议先花 2-4 周学编程基础（变量、函数、条件、循环），再用 Cursor 辅助。Cursor 能帮你写代码，但不能帮你理解代码——而理解代码是你能用好它的前提。

如果已经有了基础（学过 Python/JS，写过小项目），Cursor 是加速学习和开发的绝佳工具。

### Cursor 和 Claude Code 能一起用吗？

完全可以，而且很多人这么用。Cursor 做日常编辑和快速修改，Claude Code 做复杂重构和自动化工作流。它们不是二选一，是互补关系。

### Cursor 写的代码质量如何？

取决于你的指令质量和你审查的认真程度。AI 会犯错——写过时 API、遗漏边界情况、引入安全问题。**你审查得越认真，AI 写的代码质量越高。** 把 AI 当成需要 Code Review 的同事，而不是无需检查的权威。
