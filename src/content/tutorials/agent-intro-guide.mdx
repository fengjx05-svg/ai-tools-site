## 阅读前

这篇是写给：
- 经常听到"AI Agent""智能体"，但不太清楚到底是什么意思的人
- 想知道 Agent 和普通 AI 聊天有什么区别的人
- 想了解怎么开始用 Agent 来辅助编程的人

不需要编程基础，但如果你用过任何 AI 编程工具，理解会更透彻。

## 一句话理解 Agent

普通 AI 对话：你问 → AI 答 → 你手动做

AI Agent：你给目标 → Agent 自己**理解 → 规划 → 执行 → 检查 → 修正** → 告诉你结果

区别就一个：**Agent 能执行操作，不光是给建议。**

## 一个真实案例：两种方式改 Bug

假设你有个电商项目，用户反馈"登录后购物车清空了"。

### 用普通 AI 助手（ChatGPT）

1. 你：描述 Bug
2. AI：可能是 session 过期了，检查 `auth.ts` 里的 token 刷新逻辑
3. 你：打开 IDE，找到文件，看代码
4. 你：没看懂，复制代码贴给 AI
5. AI：这段代码有问题，应该改成 xxx
6. 你：手动修改，手动测试
7. 你：测试失败，截图贴给 AI
8. AI：再试这个方案
9. ...来回 6-7 轮

**耗时：** 30-60 分钟，取决于你对代码的熟悉程度。

### 用 AI Agent（Claude Code / Codex）

1. 你：`用户登录后购物车就被清空了，帮我找到原因并修复`
2. Agent：
   - 自己搜索代码中所有跟"购物车""登录""session"相关的文件
   - 找到 `auth.ts` → `cartService.ts` → `sessionManager.ts` 的调用链
   - 发现：登录成功后 `sessionManager.reset()` 被调用时，`cartService` 的监听器误把购物车清空了
   - 修改 `cartService.ts`：登录时保留旧购物车数据，合并而非重置
   - 运行测试：`npm test -- cartService`
   - 测试通过，告诉你："Bug 在 `cartService.ts` 第 47 行，登录时购物车被错误重置。已修复并测试通过。"

**耗时：** 2-5 分钟。

这就是 Agent 的威力——**不是回答你，而是帮你做事。**

## Agent 的四个核心能力

```
目标理解 → 工具使用 → 多步执行 → 自我纠错
```

### 1. 目标理解

你不用告诉 Agent 怎么做，告诉它要什么结果。它会自己分解成步骤。

❌ `帮我在 auth.ts 第 23 行加个变量叫 tokenExpiry，然后在第 56 行检查...`

✅ `用户的登录 token 过期后应该自动刷新，不要等报错了才处理`

### 2. 工具使用

Agent 能使用工具（这些不是比喻，是真正能执行的）：

- **读写文件**：读取项目代码，创建/修改文件
- **执行命令**：运行 `npm install`、`git diff`、`python test.py`
- **搜索代码**：在所有文件中找到相关代码片段
- **网络查询**：查文档、查 API 用法（取决于工具）

### 3. 多步执行

复杂任务 Agent 会自动拆解：

```
任务："给项目加错误监控"
→ 第1步：调研项目中现有错误处理（读 5 个文件）
→ 第2步：选择合适的监控方案（Sentry？自建？）
→ 第3步：安装依赖
→ 第4步：在关键位置加错误捕获代码（改 8 个文件）
→ 第5步：写配置文件和初始化代码
→ 第6步：运行测试确保没破坏现有功能
→ 第7步：告诉你加了什么、怎么配置
```

### 4. 自我纠错

执行过程中如果出错，Agent 会：
- 读取错误信息
- 分析原因
- 自动修改代码
- 重新执行
- 直到通过

你不需要手动"复制报错→贴给 AI→等修复→再试"。

## 怎么开始？一个入门路径

### 第1周：从 Cursor 开始

**为什么？** 图形界面最友好，学习成本最低。

1. 下载 [Cursor](https://cursor.sh)
2. 打开任何项目文件夹
3. 按 `Cmd+K`（Mac）或 `Ctrl+K`（Windows），输入 `帮我给这个按钮加点动画`
4. 看 Cursor 直接修改你的代码

### 第2周：进阶到 Claude Code 或 Codex

**为什么？** 终端 Agent 的能力上限更高。

```bash
# 尝试一个完整任务
cd your-project
claude /init
claude "帮我把所有的 console.log 替换成统一的 logger 工具，并对错误日志加上 Sentry 上报"
```

### 第3周：形成自己的 Agent 工作流

你会发现自然形成一种节奏：
- 日常小改动用 Cursor（快捷）
- 复杂重构用 Claude Code（深入）
- 学习新技术时用 ChatGPT（广度）

## 常见误区

### 误区 1："Agent 什么都能做，我可以不用动脑了"

**真相：** Agent 是你的**高级助手**，不是你的替身。
- 复杂业务逻辑还是需要你的判断（"这个促销规则对不对"）
- Agent 不懂你的业务上下文（"为什么这个订单要特殊处理"）
- 安全相关决策必须人来做（"能不能把 API Key 暴露给第三方"）

### 误区 2："任务描述越详细越好"

**真相：** 描述**目标**而不是**步骤**。

你描述"为什么"和"要什么"，Agent 自己决定"怎么做"。微管理反而限制了 Agent 的能力。

### 误区 3："Agent 的结果不需要检查"

**真相：** Agent 也会犯错，尤其在以下情况：
- 复杂业务逻辑的边界情况
- 安全敏感的代码
- 性能关键的代码路径

**黄金法则：** Agent 写的代码 = 同事写的代码。review 是必须的。

### 误区 4："Agent 只能写代码"

**真相：** Agent 能做的不止写代码：
- 写文档和注释
- 重构代码结构
- 分析 Bug 根因
- 写测试用例
- 生成 commit message
- 翻译代码注释
- 解释不是你写的代码

## FAQ

### Agent 和 RPA（机器人流程自动化）有什么区别？

RPA 是按固定规则重复操作的自动化（"每天9点从A系统下载数据导到B系统"）。Agent 是智能的——能理解目标、适应变化、处理没见过的任务。简单说：RPA 是流水线机器人，Agent 是聪明的助手。

### Agent 会取代程序员吗？

不会。Agent 改变了程序员的工作方式——从"写代码"变成了"设计 + 审查 + 决策"。程序员的价值从"打字速度"转移到了"系统设计能力"和"业务理解"。这实际上让编程变得更有趣，因为你不用花时间在重复性的代码编写上。

### 多个 Agent 能一起工作吗？

能。这是更高级的用法，叫多 Agent 协作。比如一个 Agent 负责前端，另一个负责后端，第三个负责测试。目前这个领域还在快速发展，2026 年已经出现了一些多 Agent 框架。

### 我需要什么配置的电脑才能用 Agent？

Agent 本身跑在云端（Claude、OpenAI 的服务器），你的电脑只是发送请求和接收结果。所以普通电脑就行——只要能联网、能跑终端就行。8GB 内存、任何操作系统的电脑都够用。

### "Agent 模式"和"对话模式"有什么区别？

对话模式：AI 给建议，你来执行。
Agent 模式：AI 给建议 + 自动执行。

在 Claude Code 里，大部分时候它都在 Agent 模式。在 Cursor 里，Chat 面板是对话模式，Composer 是 Agent 模式。不同工具的切换方式不同，但原理一样。
